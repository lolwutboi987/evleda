---
name: evleda-pcb
description: Create, improve, and review native KiCad PCB projects through the EvlEDA toolbox, combining available CAD operations with focused design research and native verification.
---

Turn the user's brief into a nearly ready native PCB project when the connected host provides the necessary CAD capabilities. Preserve the requested function, constraints, and deliverables; use engineering judgment to fill routine gaps and identify consequential unknowns. This skill supplies workflow guidance, not a CAD connection or project authority.

## Establish the working boundary

Call `evleda_toolbox_status` and inspect the advertised tools and their schemas. An idle workspace can provide creation tools without an open CAD session. Editing requires host-configured edit access and the existing copied-project or fresh-project authority; model arguments cannot change that access or runtime. Continue useful research when needed capabilities are unavailable, and identify what is missing before claiming native project work.

When workspace tools are advertised, use `evleda_workspace_status` and `evleda_list_projects` to distinguish a new design from an existing project. For a new design, inspect `evleda_design_schema` and its `supportedFamilies`. Select `family: "plane-v2"` for supported plane intent or `family: "routed-v1"` for the routed family; omission defaults to routed V1. Use only a family advertised by this session and read its returned schema, guide and example plus approved `evleda_inspect_library` results. Send the complete draft, original request and name through `evleda_submit_design`; the draft's exact schema version selects its compiler. Resolve returned unknowns and resubmit; clarification has not created a board. For either family's ready result, create with its ordinary `draftId`, reusing that ID after an observation timeout. Refresh tools after attachment, inspect current access through `evleda_toolbox_status`, then read the bound design context. After a server restart, resume existing designs by opaque project ID without a replacement draft or installation arguments; use read-only inspection when that is the host's configured access. Recollect current source-bound checks and previews after resume. Successful create/close/resume on an unrouted project does not establish routing or electrical acceptance.

When `evleda_search_library` is advertised, use it to discover parts in approved stock namespaces before inspecting the selected IDs. Follow single-use cursors with the same query; restart after a lost cursor response. `exhausted` ends the scan, while `complete` also requires no unsupported source coverage. A candidate's description, default footprint or datasheet link is source metadata, not electrical or pin/pad qualification. Catalog-backed compilation binds the selected source and inspection identities; source or policy drift requires a new reviewed draft before creation and rejects an incompatible saved resume. Keep the original profile for older exact-profile projects rather than silently assigning them new catalog pins.

When `evleda_design_schema` returns `approvedPackage`, its bounded symbol/footprint ID lists identify an additional host-approved local source package. Inspect those exact IDs with `evleda_inspect_library`; stock catalog search does not discover that package. Model arguments cannot install a package or change its root, manifest or approval. Source approval is separate from engineering suitability and native board verification; do not substitute a stock part or erase source identity to bypass an unsupported selected part.

Inspect the bound project's existing design and source state before choosing edits. Use only advertised operations; copied-project sessions may omit legacy schematic plan and synchronization operations. Do not infer schematic creation, synchronization, routing, or optimization capability from a tool's name. In particular, route and tuning operations may only write supplied segments or rules: inspect their actual behavior and verify the resulting geometry.

When `evleda_revise_via_budgets` is advertised, a documented engineering change may reallocate per-net via counts through a separate ready draft and a materialized source closed successfully in the same connection/profile. Only nets without a continuous-reference requirement are eligible; counts cannot fall below existing native usage. Preserve the global via limit, via geometry, clearance, widths, lengths, turn rules, reference requirements, interfaces, placement and circuit. Supply the ready draft and closed source IDs; never edit a saved bundle or rules file to change its limit. The new allocation preserves existing native geometry but inherits no acceptance or fresh-fill evidence. Explain why the new counts are suitable, verify the new design context and repeat affected native checks. A larger budget by itself fixes no connection or clearance problem.

For a fresh project, read `evleda_design_context` when advertised. Its contract, execution guidance and acceptance rows are the bound requirements, not proof of completion. Read relevant tool prerequisites before changing phases: `fresh_autoplace_schematic_fields` requires already-authored connectivity, while the separate position-only field operation below supports partial schematics. Neither establishes or repairs terminal placement. A successful schematic-to-PCB synchronization establishes neither final placement nor routing.

When `evleda_create_project` advertises `sourceProjectId`, a new ready V2 draft can retain an eligible project's exact unwired schematic after a healthy close in the same workspace connection and native profile. Keep the same project name and circuit. Only PCB placement, board width/height, existing board-feature X/Y/cardinal rotation, plane rectangle coordinates, net-class settings/assignments, routing constraints, native numeric mode and original-prompt metadata may differ. Board shape/layers, feature inventory/definitions/side/bore/clearances, other plane settings, interfaces/construction, components, values, electrical nets and library authority remain exact. Target bounds and mechanical checks still apply; verify connector pitch and mounting compatibility explicitly. The source PCB must still be its authenticated unmaterialized baseline. Supply only the ready `draftId` and closed `sourceProjectId`; the host generates new PCB/rules and records lineage without overwriting the source. Retry an uncertain create with the same two IDs. After a restart, an old project ID alone cannot recreate the close receipt: resume and close the eligible source normally in the current connection. See [schematic revisions and native rules](../../docs/toolbox-schematic-revisions-and-native-rules.md) for the narrower source envelope and examples.

When the V2 schema advertises `boardFeatures`, use it for supported board-only NPTH mounting bores with exact admitted footprint IDs, H references, poses and clearance constraints. These have no schematic symbols, electrical terminals or BOM parts. The first successful schematic sync creates the bound physical features; verify their full inventory, native disposition, drill geometry and poses afterward and on resume. Do not omit holes to fit an electrical-component limit, fake their nets, or treat a bare bore as proof of screw-head or enclosure clearance.

The host performs its narrowly checked initial native Save only for a newly prepared project, before exposing tools; it can normalize project defaults and create one exact native history snapshot. Resuming does not repeat that initialization Save. Do not create, delete or rewrite history, checkpoints or the canonical DRU to force acceptance of drift; unexpected project/source changes still require host review.

If the context identifies `family: "plane-v2"`, retain that full plane contract and its `verificationPlan`; do not convert its ground net into a trace tree or substitute a V1 acceptance plan. Inspect `copperAuthoring.incrementalRoutes` and `copperAuthoring.contractPlane` alongside the advertised tools. These report this session's edit capabilities, not completed routing, plane connectivity or electrical acceptance. A runtime that supports schematic work may still lack plane application or qualified routing transactions. Use the normal workspace ready/create path when plane V2 is advertised; readiness is compilation evidence, not a guarantee that this native runtime supports every copper operation. Plane sync/pad results distinguish physical primitives from logical terminals: inspect the actual schema rather than assuming a legacy `padCount` field.

## Develop the design with evidence

Keep a compact record of the brief, decisions, unresolved assumptions, and component sources. Verify pin functions, package pin numbering, footprints, operating limits, and necessary support circuits against the actual selected parts' authoritative documentation. Separate source-backed requirements from estimates and preferences.

Separate design decisions from verification that requires a finished board. Make defensible routine choices for the candidate's operating limits, construction targets and layout budgets, recording their basis and assumptions. A selected analysis target is not a measured waveform or manufacturer guarantee. Keep genuinely unresolved inputs null, but do not block candidate creation on procurement or physical qualification that the user deferred; retain those as explicit later checks.

Use `evleda_rule_topics` to locate relevant research. Select complete rule records with `evleda_find_rules` using at least one topic, tag, ID, category, or severity selector; follow `nextOffset` when more matching records are needed. Read a specific dossier with `evleda_read_guide` or its advertised `evleda://guides/` resource when the decision needs fuller context. Fetch only guidance relevant to the design rather than loading the entire corpus. Resolve applicability against component documentation, the intended electrical conditions, and fabrication constraints; a corpus rule is not proof that the design satisfies it.

Develop connectivity, component placement, power and return paths, and routing in an order appropriate to the board. This project's PCB trace-turn policy requires 45-degree routing unless the user explicitly changes it; do not silently relax it or apply it to orthogonal schematic wires. Justify trace widths, vias, clearances, and stackup from current, voltage, temperature rise, impedance, fabrication limits, and other applicable requirements. Do not assume a universal geometry or automatic solver.

When using an external routing proposal with protected connector regions, verify that the engine can attach to each fixed own-pad lead. A lead ending exactly on an expanded keepout boundary can remain unreachable even when its net and pad are correct. A straight inward extension may provide a usable routing endpoint, but it is new proposed copper: preserve the protected region, check the full retained scene and route budget, and require the normal source/native verification before adoption. Do not interpret this router-port failure as proof that the physical board is impossible to route. Preserve the exact required region when approximating curved reference keepouts; unnecessary expansion can also block valid routes.

Choose component orientation and placement from the actual pin locations, critical current loops, local decoupling, clock/analog noise paths, connector mating access and mechanical constraints. Whole-package rotation is separate from trace-corner geometry. Establish this placement intent before routing and check real pad, drill and body geometry; an imported or automatically scattered position is not a reviewed layout.

On larger schematics, contract connectivity can use short terminal stubs and repeated global labels instead of one long wire tree per net. Reserve label space at every source-qualified terminal group, including power pins; one free label location per net is insufficient. Coincident source-qualified pins retain every original endpoint, and NC terminals remain isolated. Inspect the actual preflight result; a failed layout returns no executable partial geometry. Large sheets still need deliberate manual symbol positioning and native drawing review.

The plane family binds its canonical `.kicad_dru` from project creation through checkpoint/resume. Do not edit it to bypass a failed requirement. Its minimum-resolved-spokes rule is not a Zone API setting or a guarantee of generated spokes: unconnected pads can be skipped by that DRC check, and local thermal overrides can take precedence. Require separate connectivity, rule applicability, actual copper and native DRC evidence. Successful rule parsing alone does not establish thermal acceptance.

When advertised by the V2 schema, select `nativeRuleMode: "contract-derived-v1"` before creation to derive native numeric floors and exact per-net/via constraints from the contract. Omission preserves legacy native settings. Optional `routingConstraints.minimumHoleToHoleMm` requires this mode and explicitly sets global edge-to-edge spacing for plated and non-plated holes; it is design intent, not fabrication qualification. Keep exact route width, channel escape, via, layer, corner and clearance checks as well as native DRC. Revise the draft and create a new candidate when bound rules must change; never patch an existing project's settings, canonical DRU or checkpoint to make a check pass.

When the user specifies an externally supplied V2 design, declare `externalPowerInputs` through the current plane schema before creation. Each entry has a unique `id` and explicit `supplyEndpoint` and `returnEndpoint`, each `{reference,pin}` naming an existing physical connector pin. Their distinct nets must have roles `power_input` and `ground`, respectively; no-connect pins are invalid. Declare each supply net once; supplies may share a return net. Keep consequential unknowns null for clarification, and omit the extension when external power was not requested. A declaration asserts an intended off-board source; it does not establish an attached supply, voltage or electrical suitability.

The host separately binds approved stock `power:PWR_FLAG` source and authors one schematic annotation per declared supply or return net through `fresh_apply_contract_connectivity`. Do not add fake driver components, BOM items, footprints, pads or physical net endpoints. Inspect the bound `externalPowerBinding` and operation results; authoring requires a qualified native connectivity producer that retains complete flag-pin groups. `EXTERNAL_POWER_CONNECTIVITY_CAPABILITY_UNAVAILABLE` requires the qualified host runtime, not a draft workaround. Require exact saved annotation/source and complete connectivity checks plus independent native ERC. Preserve power-pin errors and other findings; never infer external power from net names, suppress ERC findings or use flags to disguise a missing physical source requirement.

Use advertised `derivedPowerSources` for internal rails driven through real components. The normal supported path begins at a source-inspected `power_out` pin and crosses declared stock L/R parts to its supply anchor with an inspected ground return. An advertised `externalPowerInput` variant instead binds an existing external connector declaration through one stock Schottky A-to-K path to a `power_in` consumer and common ground. Retain source citations, operating modes and diode-drop assumptions; flags remain schematic annotations, not proof of available power or safe source coexistence. Never relabel an internal rail as external just to clear ERC. Inspect the current guide for exact supported forms before using either extension.

An intentional NC terminal can retain a generated native net name for KiCad parity while the public selection reports semantic `net: null`, `disposition: "no_connect"` and `nativeNetName`. It supplies no routing candidates: never route that net, remove its raw native name or add it as a functional contract net. Named-NC netclass/checkpoint support is currently V2 only: select advertised `plane-v2` for designs requiring it, or report unsupported scope; legacy V1 readers remain fail-closed for generated NC names. Distinguish raw named/netless physical counts from functional/NC counts. The host must bind the complete typed native netlist and current source, retain every physical member, and exclude NC tracks, vias, zones and foreign PAD reachability; a familiar net-name prefix is insufficient evidence. Repeated physical members of one NC logical terminal do not authorize connections to other terminals. During an unsaved route/plane stage, only the host may carry qualified NC authority under exact source, marker, library and saved-preimage guards; require fresh qualification after Save before relying on final results. A captured live route or stopped editor does not establish accepted persistence or successful cleanup.

When `evleda_transmission_line` is advertised and its uniform cross-section models fit the design, use it for impedance analysis or width/gap synthesis. Inputs use metres and Hz, not millimetres and MHz. Supply actual construction/material inputs; do not substitute guessed dielectric defaults. Coupled `targetOhm` is differential impedance. Inspect convergence, actual target residual, native statuses and structured model warnings. The frequency-dependent differential result and native coupled-microstrip quasistatic `Z_DIFF` are different quantities. Reanalyze actual rounded dimensions and construction tolerances before using results as a routing basis.

For uncovered microstrip, use `parameters.H_T: "absent"` with a qualified helper: protocol 3 supports single microstrip and protocol 4 adds coupled microstrip. Numeric `H_T` describes a finite metallic cover, not solder mask. A large finite height is not an uncovered coupled-model substitute. Retain the model envelope and finite-thickness assumption `S >> 2*T`; the model supplies no numerical threshold for that assumption. This bare-conductor model does not validate arbitrary construction or a saved board.

The optional V2 `interfaceRequirements` extension binds differential-pair intent before project creation. Use the current plane schema/guide to declare both member nets, all four source/receiver roles, polarity mapping, width/gap intervals, etch length/skew and uncoupled budgets, terminations, allowed signal layers, and the intended reference plane. Requirements and component sources remain explicit caller assertions; use unresolved draft values when consequential data is missing. Supported construction is explicit two-layer or bounded F.Cu/In1.Cu/In2.Cu/B.Cu four-layer, retaining every copper thickness and dielectric gap, masks, exterior, finish, material frequency and conductor metadata. Four-layer authoring requires the native runtime's matching capability; ordinary through-vias span every enabled copper layer. Select each of multiple planes explicitly and inspect each plane's own configuration and geometry. A new project receives its native construction before preparation is bound; resume preserves its existing bytes. Do not change an existing bundle or DRU through a checker to make a result pass.

For source-series USB-style channels, request `evleda_design_schema({family:"plane-v2",includeChannel:true})` and use the advertised `channel` form. Preserve the launch and line nets, actual resistor pins, every duplicated connector contact, protection-device terminal and return. Declare whole-path, branch, aggregate-copper and terminal escape budgets rather than evaluating only a central pair section. Every channel class default stays within the main body-width interval; narrow launches use explicit terminal-bound escapes and per-track widths. Supported geometry remains one signal layer without vias; unsupported channel transitions must remain visible. A bare-conductor sizing result does not validate masked routing, package internals or the complete channel.

When the selected protection device has manufacturer-documented internal input/output paths, the optional `channel.feedThrough` form represents one explicitly cited two-line transfer. It adds two input nets to the ordinary four-net channel, retaining six distinct native copper graphs and all six device pins. Source inspection checks the declared passive IO pairs and actual ground/supply roles; matching pin names alone never authorize a connection. Prove each copper graph independently and compose the channel through the declared component transfers. PCB etch length/skew includes all three copper sections per polarity; package electrical delay, skew and parasitics remain unassessed. Do not add imaginary copper between internally connected pins, merge the six native nets, or drop a physical contact to simplify routing.

Use `evleda_read_stackup` when available to inspect saved physical construction first. It distinguishes declared values, missing fields and unsupported forms, including multiple dielectric sublayers. Total board thickness is not signal-to-reference spacing, mask is not automatically the substrate, and unlike dielectrics must not be averaged into a uniform model without a justified model. Saved declarations still need their fabrication/material evidence; the reader does not select a reference plane or certify impedance.

When `evleda_check_microstrip_route` is advertised, first read `evleda_read_stackup` and use its `sourceIdentity` as `expectedSourceIdentity`. Select the net, outer signal layer, exactly two component-reference/pad terminals and adjacent reference net/layer/zone; provide the numerical target/tolerance, matching frequency and explicit construction/material metadata. The host derives width, length and stackup from saved bytes. Support is limited to a bare uniform single-microstrip chain: missing or positive mask thickness and unsupported construction remain unassessed, while fully inventoried ordinary other-net vias can be retained. Caller metadata is not verified material evidence. Inspect numerical target, model limits and reference requirements separately; source centerlines do not prove physical DC, finite-width contacts, reference freshness or impedance accuracy. This read sets no requirements and grants no board/interface acceptance or differential-pair support.

For a bound pair, call `evleda_check_interface` with only its `interfaceId` from `evleda_design_context`. The host reads settled saved/native state and derives limits from the authenticated contract. Inspect both complete source routes, exact etch lengths/skew, paired and uncoupled intervals, all track-pair gaps, source polarity and termination observations. Selected vias, ambiguous correspondence or unsupported pad geometry must remain visible; a favorable central segment cannot establish complete-route compliance. Nominal impedance calculations use the actual supported paired intervals and saved construction. Their targets can match while launches, bends, finite-thickness applicability, termination resistance or physical return-path requirements remain unresolved. Read the report and retain its private diagnostic identity; no model argument can supply paths, source bytes, evidence, geometry or replacement targets. This check neither routes/tunes the pair nor replaces native checks and fresh reference coverage.

When advertised, `evleda_check_reference_coverage` checks actual saved straight segments against selected saved zone-fill contours. Select signal nets/layer and the intended reference net/layer; supply a justified geometric margin beyond the trace edge in integer nanometres and retain its basis. This operation neither refills the board nor chooses an electrically valid reference. Inspect omitted IDs and unsupported geometry before extending a subset result to a whole route. Keep `covered`, `uncovered`, `boundary_uncertain` and `not_assessed` distinct. A covered result can still involve stale fill or an isolated island; require separate fresh-fill, terminal connectivity, layer/stackup and interface evidence before accepting the return path. Divide each `outsideWitnessDoubledNm` coordinate by two to obtain nanometres. Diagnostic clipping polygons are conservative, not exact missing trace area. Their hash-bound resource is a historical snapshot and can outlive the active project.

A calculator result is explicitly not saved-board verification. Preserve its inputs/model provenance, then check applicable pair polarity, width/gap, skew, discontinuities, termination and continuous return reference on the actual layout. Respect reported model limits, including the coupled-stripline piecewise boundary and potentially nonunique inverse; do not turn a converged answer into physical accuracy or manufacturing assurance. If the active authoring contract cannot represent the needed impedance/pair requirements, report that missing capability rather than disguising the channel as ordinary unrelated nets.

## Edit and verify the native result

Make coherent, reversible edits within the bound project's authority. Inspect mutation results and the existing save/readback outcomes before proceeding. If `recoveryRequired` is true or an operation reports `recovery_required`, stop edits; the owning host must inspect/recover and establish a new session. Do not retry an uncertain mutation blindly.

When advertised, `fresh_set_schematic_field_positions` atomically updates 1–128 unique `{reference, field, x_mm, y_mm}` entries for existing `Reference`/`Value` fields, including before connectivity or with a partial component inventory. Coordinates are stored sheet coordinates in exact 0.0001 mm units. Only the selected X/Y tokens change; strings, angles, justification, visibility, fonts, electrical content and UUIDs stay exact. Inspect mandatory save/readback and native netlist-equivalence results, then review the render. Literal-text glyph candidates are diagnostics, not proof of field ownership or whole-sheet readability.

Use `fresh_set_schematic_symbol_poses` for 1–64 unique `{reference, x_mm, y_mm, rotation}` updates only in its supported unwired fresh source; `rotation` is 0, 90, 180 or 270. All placed references must belong to the contract. Wires, labels, NCs, flags, junctions, buses, child sheets, mirrors and unsupported forms reject, including on unselected instances. It changes only instance X/Y/rotation tokens and preserves every field token, so reposition retained fields separately with the field tool when needed. Native netlist equivalence rejects new or broken coincident-pin connections. These operations use the host's atomic owned-source stage, exact file/source checks and mandatory save; an unknown replacement source is preserved for recovery rather than overwritten. They do not provide a connected-schematic transform or claim an editor GUI reload.

For physical fresh projects, the advertised footprint-move/place operations use host-owned preserving placement. Supply the component reference and supported pose; current support is front-side cardinal rotation with exact integer-nanometre coordinates. The host retains pad properties, models and unrelated source, reproduces characterized native graphic ordering, and requires native reload/save/readback. Unsupported forms reject. Inspect the persistence result and exact physical pads before routing; a successful move or saved model reference does not establish electrical or mechanical suitability. Do not bypass a source mismatch with a raw footprint rewrite, dropped metadata or relaxed comparison. Placement invalidates previous plane-fill evidence.

When `fresh_set_footprint_poses` is advertised, apply reviewed poses together using `placements: [{reference, x_mm, y_mm, rotation_deg}]`, with 1–64 unique existing electrical references and all four fields present. Each exact integer-nanometre front-side pose must satisfy its declared region and allowed cardinal rotations. The complete batch validates before staging; a changed batch uses one native reload and one mandatory save/readback while retaining the full physical inventory and immutable board features. Inspect the completed persistence result and then recollect placement/clearance/fill evidence. This operation does not choose placements or certify clearance; see [batch placement details](../../docs/toolbox-schematic-revisions-and-native-rules.md#place-existing-pcb-footprints-in-one-batch).

When advertised, `fresh_set_footprint_fields` applies a bounded atomic `updates` list to existing `Reference` or `Value` presentation. Select the exact reference and field; positions use absolute board coordinates and cardinal text angles. The tool preserves field strings and electrical/physical geometry while changing supported visibility, position, size, stroke or F.SilkS/F.Fab layer. Prefer clear functional board labels and readable assembly references; do not move electrical parts merely to fit stock reference text. Inspect mandatory persistence, then regenerate native previews and DRC. V2 `pcb_add_text`, when advertised, adds separate board text under its existing guarded save/readback path; it does not edit footprint fields or establish silkscreen clearance.

For plane-family copper work, establish the outline and placement, then inspect actual physical pad positions. When advertised, obtain a current `fresh_get_route_items` selection before `fresh_replace_route_items`; follow its schema for the selected net, exact deletion IDs and proposed segments/vias. Incremental ground-access stubs and partial signal routes need not form a completed trace tree, but they still require the specified widths, vias and 45-degree turns. A successful incremental edit does not establish clearance, plane contact or complete connectivity.

Large V2 route selections use 32-item public pages while retaining the complete private inventory. Start with `{}` and pass the exact returned `pagination.nextPage` as the next call's `page` until it is null. The top-level `identity` binds the complete selection and is the identity used for edits; `pageIdentity` binds only that page. Source drift, skipped pages and replayed continuations reject. After a lost page response or a relevant edit, restart with `{}` rather than inventing a cursor or treating the visible page as the entire board. Whole-board capacity does not enlarge the per-mutation track, via or deletion limits.

Verify via spacing through current native DRC as well as exact dimensional/net readback. Check copper, drilled-hole and board-edge clearances and annular ring under the bound rules; warnings count as findings in the qualified all-severity check. Missing or ignored required via checks cannot establish a pass. Ordinary electrical clearance does not establish every same-net physical spacing requirement, and a requested via net is not evidence of the net retained by KiCad after loading or saving.

Use `fresh_apply_contract_plane` when advertised, selecting only the bound contract's plane ID when needed. The host derives the rectangle, net, layer and fill settings, and creates or updates the owned plane; do not supply a guessed zone UUID or raw replacement geometry. Reapply after edits that invalidate the fill before relying on saved copper coverage. Inspect the public operation's persistence result: the native stage itself never saves, and an update with `sourceChanged: false` still needs the host's mandatory native save because refill can dirty the editor without changing serialized bytes. Do not infer thermal spokes, island-area compliance, intended-plane contact, DC connectivity or high-frequency validity from APPLY success. Obtain the applicable saved-state evidence separately and keep unsupported acceptance rows unresolved.

When advertised, call `evleda_check_endpoint_connectivity` with `{}` on the settled saved V2 project. The host derives every physical endpoint and collects individual native PAD queries; do not supply paths, endpoint IDs, PAD requests or raw native observations. Inspect each net's status, logical reachability and `everyEligiblePhysicalMemberReachable`, together with source stability and the reported limitations. A logical connection with split physical members still needs review; do not invent component-internal ties. After a relevant edit, save and collect new evidence.

The compact public report uses `evleda.toolbox-endpoint-connectivity.v1`; its full raw assessment remains an immutable host-private diagnostic identified by filename and hash. Neither that diagnostic nor a connected result authorizes private file access or promotes a verification-plan row. Require separate intended-plane contact, qualified refill, thermal/spoke/island, cross-net-short and reference-path evidence where applicable. The V2 practice analyzer is profile-free: literal turn checks and the route writer's numerical width/via enforcement do not establish ampacity, HF/impedance or manufacturing suitability.

When advertised, call `evleda_check_plane_acceptance` with `{}` after the current session has reapplied the bound plane and completed mandatory save/readback. Repeat APPLY/save after relevant edits or reopening before relying on fresh plane facts. The read tool does not refill; old saved polygons, checkpoints and private diagnostics cannot recreate current-session fill authority. Missing fill leaves dependent plane/reference rows unknown; independent saved interface facts and failures remain reportable. Stale or conflicting evidence rejects. In a read-only resumed session, report the missing fresh-fill capability instead of supplying evidence or changing access through model arguments.

On read-only reopen, verify the same saved bundle and source identities, then collect current endpoint and preview evidence and finish normally. Connected endpoints and a byte-identical preview do not restore the prior session's fill witness or acceptance rows. Report the current read-only plane result as returned, including unknown rows and `accepted: false`; retain the earlier edit-session assessment separately. Confirm normal close and unchanged saved sources before claiming a successful reopen lifecycle.

Read every `pass`, `fail` and `unknown` verification row and the remaining mandatory rows. Distinguish stored-fill area from the conservative drill-subtracted lower bound and inspect every retained bore classification. Native PAD-graph contact to a stored component does not prove global drill-clipped pad, track and barrel continuity; withhold a pass for the whole plane-net and reference rows while that gap remains, even if native connectivity or geometric coverage facts are verified. Preserve every explicit failed row; the continuity gap must not turn a failure into unknown. Exact bore/ribbon overlap fails; tangency is uncertain. Preserve every bore record and definite local ribbon failure even if another bore leaves global topology unknown. Do not dismiss a small strict nominal drill/polygon intersection as numerical noise or waive it to obtain a pass. Read complete native findings and their component/pad mappings to resolve concrete parity, clearance or connectivity issues rather than treating a generic failed thermal/DRC fact as the diagnosis. A native minimum-spoke lower bound is not a measured count or width. Actual minimum copper and thermal widths remain unmeasured or inapplicable as reported. The current `accepted` and `fabricationAuthorized` values remain false; do not promote scoped facts to HF/impedance or ampacity approval.

Inspect each plane's own thermal-policy result. A pad marked `pad-copper-outside-declared-plane-boundary` has a conservative source/native geometry proof that all its copper is strictly outside that plane's rectangle; only the local zone-contact/thermal setting is inapplicable. This does not prove its inward access track, endpoint connectivity, intended-plane return or overall acceptance. Pads touching or overlapping the boundary are not exempt, and contradictory native direct contact rejects. Ordinary oval shield pads and their exact mechanical fabrication marker retain the same complete geometry, contact and override checks as other supported pads.

When reported, `planeRegionBridges` is an additional observation for supplemental ground regions. A verified result requires every region to have a positive-area copper contact disc in a qualified normal through-via annulus and the endpoint-anchored primary plane, clear of all conservatively enclosed bores. It also requires matching current native direct-via contacts on both zones and complete source/native geometry. Missing witnesses remain unproven. This observation does not waive a declared single-component policy, establish complete drill-clipped continuity or current capacity, or authorize a design revision. Preserve the original failed rows while reviewing any proposed policy change separately.

Use `evleda_validate_design` when available to collect native checks and source fingerprints. Inspect each ERC, DRC, board summary, and visual QA result, including errors, omissions, and whether the sources changed during collection. Retain each checker's ignored categories when reporting zero configured findings; do not present them as unrestricted checker coverage or proof of a separately required strict schematic-parity check. Preserve NC identity conflicts and stock pad-property/thermal-override findings for diagnosis instead of removing physical metadata to satisfy a checker. Review rendered board views for placement, routing, labels, outline, and mechanical intent; tool success alone is not visual inspection. Resolve relevant findings, rerun affected checks after changes, and tie the final evidence to the saved design state.

When advertised, `evleda_render_board` returns a native saved-board preview: use `top` for copper/silkscreen/outline and `assembly` for fabrication text/pads/outline. Inspect the returned PNG and retain its exact SVG resource when useful. These are saved-source snapshots, not a live editor view; render again after changes. Assembly text outside the board remains visible and is a finding, not something to hide by cropping. Historical resources can remain readable after finishing the session without representing the current board.

Use the advertised `pcb_add_text` only for its supported literal front-silkscreen labels; inspect its schema for current size, rotation and text limits. It adds new board text, not footprint-field edits or removal. Place signal names against verified connector pin positions and orientation, then check legibility and copper/mask clearances in native views and DRC. A text anchor inside the outline does not prove the whole string fits. Do not infer connector polarity from an unkeyed footprint or replace an existing field by overlaying another label.

Also inspect `evleda_check_board_practices` or the practice result included in validation when available. Address literal turn-policy violations and any bound width/via findings. Its measured straight-segment subset is not whole-board coverage: unresolved junctions, overlaps, reversals or arcs require investigation. Missing electrical/profile inputs remain unverified even when the measured geometry has no violations. The numerical angle tolerance is not permission to relax the required routing policy.

Before disconnecting a native session, call `evleda_finish_session` when advertised and wait for its result. It closes the owned editor and publishes a saved-candidate checkpoint when supported; it does not approve the design. Resume through the host using the saved bundle, not a new intent disguised as continuation. If finalization is uncertain or a dialog prevents closing, report it and preserve the state; do not edit checkpoints or remove unproven locks to force a resume.

In workspace mode prefer `evleda_close_project` with the active ID; it finishes, checkpoints, releases the owned lease and detaches CAD tools. Wait for confirmation before another project or disconnect. A failed/uncertain startup or close requires host review, not deleting lease/admission files. Uncreated drafts may be discarded from memory with the dedicated draft tool; that does not delete native projects.

Deliver the native project location, implemented behavior, material decisions, actual verification results, and remaining work or uncertainty. Do not label a design nearly ready while material electrical or layout requirements remain unverified; report a candidate needing review instead. Clean native checks alone do not establish functional, thermal, or electrical suitability, and neither this skill nor a design review is manufacturing approval. Manufacturing release, firmware, and other campaigns belong in the work only when the user's scope includes them.
