## Measured native behavior

Each fixture has one B.Cu GND zone and two intended GND pads. The positive connects around a rectangular cutout. The negative uses a 0.10 mm neck below its explicit 0.25 mm minimum fill thickness; refill removes the neck, leaving two pad-connected islands under the same zone UUID. Island removal is explicitly `never` in this fixture, not an implicit production policy.

| Native observation | Connected positive | Disconnected negative |
| --- | --- | --- |
| Filled polygons returned over IPC | 1 | 2 islands |
| PAD-filtered query from the first pad | Both intended pads | First pad only |
| PAD-filtered query from the second pad | Both intended pads | Second pad only |
| Query from the zone or both pads together | Both pads | Both pads; not evidence they connect |
| Typed `PolygonWithHoles.holes` entries | 0 | 0 |
| Holes restored by native `Unfracture` | 1, with area unchanged | 1, with area unchanged |
| Native DRC general violations / missing connections | 0 / 0 | 0 / 1 |

`get_connected_items` includes the source item itself and returns the union of the source items' native copper-connected clusters. The PAD filter limits returned item types, not traversal through intervening copper. Therefore each intended endpoint must be queried separately. A zone may participate in more than one disconnected cluster; a zone-origin or multi-pad-origin union cannot prove that the endpoints connect. The negative DRC can name the same zone UUID twice because the disconnected parts share that UUID.

Filled contours are fractured: overlapping bridge edges connect an inner void's contour to the outer contour. Consequently an empty typed `holes` list does not prove there is no void. The captured saved native fill vertices exactly match the IPC vertices. `SHAPE_POLY_SET.CloneDropTriangulation().Unfracture()` on a copy restores the holes without changing area or either saved board. This is an observed native interpretation path, not permission to ignore unsupported geometry or invent a second connectivity engine.

## Refill epoch: source semantics and isolated qualification

All source links in this section pin KiCad 10.0.3 commit `146a4f2a7585c65bc580427a19b6fe2ec4a3f622`.

- [`handleRefillZones`](https://github.com/KiCad/kicad-source-mirror/blob/146a4f2a7585c65bc580427a19b6fe2ec4a3f622/pcbnew/api/api_handler_pcb.cpp) schedules `zoneFillAll` through `frame()->CallAfter` and returns `Empty` immediately. There is no returned job ticket or exposed refill epoch. The [protobuf commentary](https://github.com/KiCad/kicad-source-mirror/blob/146a4f2a7585c65bc580427a19b6fe2ec4a3f622/api/proto/board/board_commands.proto) promises subsequent busy responses, but does not establish the implementation's actual gating for every command.
- [`handlePing`](https://github.com/KiCad/kicad-source-mirror/blob/146a4f2a7585c65bc580427a19b6fe2ec4a3f622/common/api/api_handler_common.cpp) returns `Empty` without a busy check; the [server dispatcher](https://github.com/KiCad/kicad-source-mirror/blob/146a4f2a7585c65bc580427a19b6fe2ec4a3f622/common/api/api_server.cpp) supplies no universal busy gate. A successful Ping can therefore occur without proving the queued action's completion. `SaveDocumentToString` is also not busy-gated and can expose intermediate state.

## Acceptance invariants: DC and high-frequency claims are separate

**DC endpoint reachability:** KiCad must establish that the exact intended pads are physically copper-connected, with correct net assignments and separate current native DRC. Sharing a net label or zone UUID is insufficient. The public adapter now enforces individual physical-member queries, and the complete proof observes all nets connected. It does not infer component-internal ties when physical members are split, or establish intended-plane contact, cross-net-short absence, effective island policy or a fresh refill epoch.

**High-frequency reference continuity:** Actual filled reference copper must support the full selected signal route without an unapproved gap, split, or edge crossing. Check the route's projected geometry against filled polygons and holes, using any required lateral margin from the bound interface/stackup profile. A distant DC-connected bridge around a slot does not satisfy this check.

Every plane result must bind the exact contract, zone settings, filled geometry, saved PCB, rules, tool identity, and native reports. Mutation after capture invalidates the result. Missing/unsupported fill geometry or unavailable native evidence cannot produce a pass. Keep ordinary route/width/via rules active for the track portions and nets within their scope.

A true implemented plane capability includes contract ownership, native creation/refill/save, source-bound native connectivity, filled-geometry evidence, and reference-continuity acceptance. Parser permission alone supplies none of those claims.
