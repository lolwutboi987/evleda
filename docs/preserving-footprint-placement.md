# Preserving footprint placement

Physical fresh projects use a host-owned source edit for `pcb_move_footprint`, `pcb_move_component` and `pcb_place_component`. The arguments remain reference, position and rotation. The host checks the current saved/native board and stock physical inventory, changes the selected footprint's pose, reloads the owned board, and requires native save/readback before completing the public operation.

This avoids a demonstrated limitation of the pinned KiCad 10.0.3/KiPy path: whole-footprint protobuf updates cannot represent the heatsink fabrication property, and the installed KiPy rotation setter omits 3D-model children. The pinned [native update handler](https://gitlab.com/kicad/code/kicad/-/raw/146a4f2a7585c65bc580427a19b6fe2ec4a3f622/pcbnew/api/api_handler_pcb.cpp) replaces the footprint; [footprint deserialization](https://gitlab.com/kicad/code/kicad/-/raw/146a4f2a7585c65bc580427a19b6fe2ec4a3f622/pcbnew/footprint.cpp) rebuilds its children. The source path retains their complete saved representation.

The [planner](../src/harness/fresh-footprint-placement.ts) supports characterized front-side cardinal placements and exact integer-nanometre coordinates. It retains UUIDs, pad-local coordinates, nets, fabrication properties, models and unrelated source. It updates root, pad and text angles according to the pinned format and emits the native order of supported graphical forms. Complete subtree contents stay intact when their order changes. Unsupported forms or ambiguous ordering keys reject; the general board comparator and numerical tolerances are unchanged. This preserves the current model references and settings, without certifying the models' physical accuracy or adding stock-model inventory approval. Other legacy or copied-project paths are outside this qualified fresh-project placement flow.

The [persistence boundary](../src/harness/fresh-board-persistence.ts) checks source identity and file ownership before staging. The host verifies edit authority before writing and invalidates previous plane-fill evidence. A native reload is followed by complete source/physical checks and the mandatory save. A failed operation retains its primary phase and available snapshots through the [private diagnostic writer](../src/mcp/toolbox-footprint-placement-diagnostics.ts) before guarded recovery. Diagnostic publication is bounded and best-effort; it cannot conceal the original failure or justify overwriting an unknown editor/file state.
